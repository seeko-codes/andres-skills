# Dispatch briefs

Use one skeleton for every child. A long brief is usually a badly cut slice.

## Shared skeleton

Every brief contains:

- **ROLE:** one line of orientation, not flattery.
- **TASK:** done-condition, not an activity list.
- **ANCHOR:** smallest owning subtree; orient at its routing file, never repo root.
- **INPUTS:** curated file table with `read fully`, section, or on-demand and why. The matching
  doctrine file is row one and is read fully.
- **BOUNDS:** the work-alone line from `doctrine/core.md` verbatim, exact write-set, isolation, and
  local law.
- **DONE:** externally checkable completion condition.
- **REPORT:** conclusions for the orchestrator, normally no more than 1–2K tokens.

## Decode additions

Add the standing **QUESTION** and the orchestrator's written **PREDICTION**. The report is the delta
against that prediction. Fully predicted means a one-line coverage pointer.

Read [doctrine/decode.md](doctrine/decode.md) fully.

## Execution additions

Add the frozen **CONTRACT**, pre-pinned failing **CHECK**, and the stop-on-undecided line from
`doctrine/execute.md` verbatim. Code slices explicitly load `lean-quality`, run its full pass, and
report each instrument and result. The worker starts only after the check is observed red.

Read [doctrine/execute.md](doctrine/execute.md) fully.

## Adjudication additions

Add the **DESIGN** at stake, assigned **LENS**, and commit-before-compare instruction. The report is
verdict-sized.

Read [doctrine/adjudicate.md](doctrine/adjudicate.md) fully.

## Context hygiene

A fresh child sees only what auto-loads and what the brief invites. INPUTS is an allowlist, the
write-set bounds exploration, and anchor-first orientation keeps unrelated subtrees untriggered.
Expertise comes from complete coverage of the named corpus, not `read everything under X`.

The project's dispatch-anchor map, when present, is authoritative. A line beyond this skeleton must
earn its place by carrying a pinned fact, invariant, or decision the child cannot derive.
