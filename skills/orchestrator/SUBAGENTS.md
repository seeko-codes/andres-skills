# Native runtime adapters

Use the active session's native dispatch, status, messaging, cancellation, and completion
controls. Inspect the actual schema. Do not substitute detached coding-agent CLIs or claim
another runtime's controls exist here. General-purpose agents get temporary assignments
through briefs; profile names do not establish expertise. Preserve available tools unless
user or runtime restrictions apply; constrain work through contracts and write ownership.

## Capability and context

Select supported model and effort parameters only. Manager roles request the smartest
available model at maximum supported effort; report inherited or immutable settings honestly.
Inspect context-occupancy telemetry and link each measurement to its run. Where absent,
apply the unknown/estimated fallback in [CONTEXT.md](CONTEXT.md). These Markdown instructions
do not install a background monitor or add capabilities to the runner.

## Isolation and completion

Prefer managed worktrees for writing agents. Otherwise create and verify separate worktrees
and put absolute paths in briefs. Shared cwd is not isolation. If work is necessarily a
local gitignored artifact, explicitly bound its separate staging path and ownership.
Track run completion through native controls, then inspect outputs and verification evidence.
A status label or report file alone does not establish success.

## Codex

Use native spawn/message/wait/status/interrupt tools. Full-history forks may prevent model
overrides and carry irrelevant context; use a focused brief/fork when supported. A child may
share the filesystem, so explicitly establish isolation. Respect runtime limits on agent
depth, concurrency, model choice, and tool use even when Wayfinder mode requests more.

## Claude

Use the exposed native Agent/Task and supported background/resume controls. Prefer managed
worktree isolation when available, otherwise explicit worktrees. Do not require Pi or Codex tools.

## Pi

Read [PI-RUNTIME.md](PI-RUNTIME.md) only in Pi. Use the live native subagent schema and
tracking controls. Do not assume installed profiles, registries, or workflow shapes.

## Wayfinder and handoffs

A Wayfinder may commission an orchestrator with permission to commission leaf workers only
when the runtime permits that depth. Keep one active owner of each horizontal goal. Renew a
manager through a supported successor dispatch/resume mechanism with a compact checkpoint;
never claim to clear a human chat or transfer inaccessible run handles. If depth is unavailable,
keep the Wayfinder function in the main manager and use one worker layer, explaining the limit.
If no native delegation exists, perform feasible work locally and report the unavailable benefits.
